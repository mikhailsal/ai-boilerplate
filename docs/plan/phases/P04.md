# P04 Implement the test and coverage engine

Status: DONE

Implementation commit: `86fbed1` (feat(tests): add the test and coverage
engine).

## Delivered

- `run_suites` runs, for each selected component, its declared suites through
  a profile runner, then enforces the unit coverage floors of `quality.toml`
  for that component alone. The design is recorded in
  [decision 0008](../../decisions/0008-test-and-coverage-engine.md).
- Runner protocol (`ProfileTests`): which source files the profile must
  account for, how to run one suite into a new output directory, and how to
  parse its coverage report. The Python runner and the command that calls the
  engine follow in P05.
- Native report parsers, each cross-checking declared counts against its
  records:
  - coverage.py JSON format 3;
  - LCOV, including merged repeated blocks and branch expressions with commas;
  - Clover in PHPUnit's shape;
  - JUnit XML, including nested suites and the outcome precedence error,
    failure, skipped.
- Evidence rules:
  - reports must be regular files inside the run's new output directory and
    not older than it;
  - a runner exit status other than 0, a failing test, or zero executed tests
    fails, and coverage from that run is never read;
  - skipped tests warn;
  - only unit runs feed the coverage floors.
- Expected sources come from the snapshot inventory, not from imports. An
  omitted file fails with `coverage.unaccounted`. Report entries that are not
  the component's expected sources are ignored.
- Floors use exact integer comparisons: line, branch, changed lines (from the
  commit diff), and new files. Not applicable (`0/0`) is information only when
  every source root exists; otherwise `coverage.no-source` fails. A report
  without branch data is an environment error.
- Scope: affected components plus their reverse dependencies; the policy, the
  core, and unowned non-documentation paths select every component; renames
  count on both sides. CI can select every active component.
- `tests.*` and `coverage.*` findings cannot be excepted.
- Testkit: `FileSpec`, `coverage_json`, and `junit_xml` build consistent
  reports, and `ScriptedRunner` writes scripted reports for engine tests.
- Documentation: decision 0008; decision 0007, `AGENTS.md`, and the core
  README updated; `quality.toml` declares the new `coverage` and `testing`
  layers.

## Limitations and follow-ups

- No runner is registered yet: the Python runner, the command, and hook
  integration arrive in P05, the other profiles in P06–P08. Until then the
  engine is proven with scripted runners and real native report samples.
- The Clover and PHPUnit JUnit samples are hand-made in PHPUnit's shape. Real
  PHPUnit output replaces them in P08.
- The Vitest samples come from Vitest 3.2.4, run in a scratch directory.
  Decision 0005 pins Vitest 5.0.5, whose reports P06 must exercise.
- A forged report written by malicious test code inside its own output
  directory cannot be detected; decision 0008 lists this residual risk.
- Exports (LCOV, Cobertura, JUnit), regression reports, and CI reruns belong
  to P10.
