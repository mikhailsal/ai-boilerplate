# P05 Complete Python and activate the strict hooks

Status: DONE

Implementation commit: `5231fb9` (feat(python): add the Python profile,
launcher, bootstrap, and strict hooks).

## Delivered

- Python profile ([decision 0009](../../decisions/0009-python-profile.md)):
  - configuration checks (`python.config`): a `pyproject.toml` project
    table, an exact `.python-version` pin, a `uv.lock` that locks pytest and
    coverage, explicit Ruff selection without blanket ignores, and pytest
    paths inside the repository;
  - Ruff format and lint, and Pyright in strict mode, run on the candidate
    snapshot with the pinned tools of the core environment;
  - pytest suites with coverage.py branch measurement of the source roots,
    in an environment synced offline with `uv sync --frozen` and a fresh
    home and temporary directory;
  - safe fixes (`quality fix`): Ruff fixes and formatting in the working
    tree, never staged.
- Launcher and hooks ([decision 0010](../../decisions/0010-launcher-bootstrap-and-hooks.md)):
  - `./quality` runs on the system `python3` with the standard library;
    `bootstrap` installs the SHA-256-verified uv and the pinned CPython and
    syncs the core; every other command syncs offline first;
  - `quality bootstrap` installs gitleaks, provisions each component of the
    staged candidate, and installs the check-only `pre-commit` hook, plus
    `pre-push` with `--pre-push`. A foreign hook or `core.hooksPath` is
    `hooks.conflict` and is left unchanged; `<name>.local` hooks run first;
  - `quality doctor` checks the setup offline and read-only;
  - `quality test` and `quality self-test` run the declared suites.
- Validator provenance
  ([decision 0004](../../decisions/0004-candidate-snapshots.md#validator-provenance)):
  `check`, `test`, and `self-test` are judged by the candidate's own core. A
  working-tree core that differs hands the command to the materialized
  candidate core; a differing core lockfile fails with `core.environment`.
- The core (`quality-core`) and the launcher (`quality-launcher`) are tooling
  components of this repository with unit suites, and the core has an
  acceptance suite (`tools/quality/tests/acceptance`). It drives real
  `git commit` and `git push` calls through installed hooks in scratch
  repositories.
- This repository's hooks are installed with `./quality bootstrap --pre-push`.
  The implementation commit went through the pre-commit hook, which ran the
  unit suites of both components with their coverage floors.
- Defects found and fixed, each with a regression test:
  - modules named like configuration files inside source roots (`setup.py`,
    `conftest.py`, `noxfile.py`, `*.config.js`) were classified as
    configuration and skipped lint, types, structure, and coverage. Reverting
    the fix lets a commit with an unused import in `src/app/setup.py` through;
    they are now source
    (`acceptance/test_commit.py::test_modules_named_like_configuration_are_checked_as_source`,
    `discovery/test_classify.py`);
  - every `setup.py` marked a package, so `engine/setup.py` in the core was
    reported as a manifest outside its component; only one that imports
    setuptools or distutils marks a package now (`discovery/test_manifests.py`);
  - `quality fix` listed a fixer that failed to run as fixed
    (`engine/test_fixes.py::test_a_fixer_that_cannot_run_is_reported_and_not_counted`).
- Documentation: decisions 0009 and 0010; the
  [command-line reference](../../reference/cli.md); decisions 0002, 0003,
  0004, 0006, 0007, and 0008 amended; `AGENTS.md`, the root and core READMEs,
  and the documentation index start from `./quality bootstrap`.

## Limitations and follow-ups

- Unit tests are not isolated from the network; decision 0009 records this.
  The remaining part of R06.9 is open.
- Local hooks are advisory: `--no-verify`, a deleted hook, or
  `core.hooksPath` skips them. The CI gate in P10 is the boundary.
- The provenance comparison itself, the CLI entry point, and the launcher run
  from the working tree. `--rev` of a commit whose core lockfile differs from
  the working tree fails with `core.environment`, and so does the pre-push
  hook for such a tip (decision 0004).
- The scratch acceptance repositories run the core under test through a small
  entry point, not the launcher; the launcher is covered by its unit suite
  and by this repository's hooks. P11 repeats the flow in a fresh export.
- `./quality bootstrap --help` runs the launcher's download steps before the
  core prints the help text.
- The acceptance suite runs on the pinned CPython only; TypeScript, Dart,
  and PHP profiles and mixed projects follow in P06–P08.
