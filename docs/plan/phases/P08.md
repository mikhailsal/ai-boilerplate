# P08 Complete PHP

Status: DONE

## Delivered

- PHP profile ([decision 0013](../../decisions/0013-php-profile.md)):
  - runtime: the system `php` of the standard system directories at the
    minor version of `[runtimes.php]`, with Xdebug of `[runtimes.xdebug]`
    loaded by the system or with `-d zend_extension=xdebug`. The runtime is
    probed once per process; a PHP without Xdebug, one with only PCOV, or
    one with the wrong minor versions fails `check`, `test`, and `doctor` with
    an environment error naming the prerequisite;
  - configuration checks (`php.config`): a composer.json that
    `composer validate` accepts, with `vendor-dir` at `vendor` and PSR-4
    directories inside the repository, and a current composer.lock that
    locks the pinned PHPUnit, php-code-coverage, PHPStan, and PHP CS Fixer
    from zip archives over HTTPS, every other source over HTTPS, and path
    packages inside the repository. A committed `vendor/` is rejected. The
    component's `.php-cs-fixer.php`, `phpstan.neon`, and `phpunit.xml` are
    never read or executed;
  - installation: `composer install --no-scripts --no-plugins` into the
    snapshot from the shared Composer cache with the network disabled, once
    per component and work area;
  - PHP CS Fixer with `@PER-CS` (`php.format`) and PHPStan at level max
    with no baseline (`php.types`), under the gate's own settings. Each
    PHPStan error carries its identifier as the symbol, so a reviewed
    exception names one identifier in one file; PHPStan runs behind the
    network isolation because it loads the component's autoloader;
  - unit suites through the component's PHPUnit with a generated
    configuration and bootstrap: the bootstrap loads every source file that
    only declares, the source filter is every `.php` file of the source
    roots without tests and `vendor/`, uncovered files included, branch
    coverage on, `@codeCoverageIgnore` disabled. Lines come from PHPUnit's
    JSONL report and branches from Clover, cross-checked against each other;
    a file with functions but no measured branch fails as unmeasured. A run
    that leaves no or empty JUnit results could not start, and the failure
    quotes PHPUnit's reason;
  - safe fixes (`quality fix`): `php-cs-fixer fix` in a temporary copy
    without `vendor/`, copied back only over unchanged working-tree files.
- The PHP helper `tools/quality/helpers/php`, a PHP program on the pinned
  nikic/php-parser with its own composer.lock, installed once per digest of
  its files and the PHP version. It measures functions, complexity, nesting,
  lines, and names with the counting rules of decision 0007 (closures, arrow
  functions, property hooks, anonymous classes), resolves `use`
  declarations, class names through PSR-4, and literal `include` and
  `require` paths, and says which files only declare and how many units
  each has. It is a `helper` component of this repository with 65 tests at 100% line (253/253) and branch (330/330).
- Coverage: a PHPUnit JSONL parser (`coverage/phpunit.py`); the Clover parser
  now returns statement records and totals for the cross-check; the
  coverage model marks a file whose branches were not measured, which
  `coverage.branch-unmeasured` reports.
- Toolchain: Composer 2.10.3 is a SHA-256-verified PHP archive of
  `tools/quality/toolchains.toml`; the Composer packages every component
  must lock are pinned under `[packages.composer]`, and the PHP and Xdebug
  minor versions under the new `[runtimes]` table. Bootstrap installs
  Composer, fills the Composer cache, and installs the helper only for a
  PHP component; doctor repeats the installation offline (decision 0010).
- Engine: the candidate's core is materialized when the PHP helper's
  sources or manifests differ from the working tree's; a helper answer may
  carry a `failure` reason (`adapters/helperio.py`). The candidate selection
  and coverage lines that `check`, `test`, and the provenance step share
  moved to `cli/verdict.py`.
- Testkit: a fake PHP and Composer (`testkit/phpfakes.py`) and scratch PHP
  components locked offline from the helper's lockfile
  (`testkit/phpproject.py`).
- Documentation: decision 0013; decisions 0001, 0002, 0005, 0007, 0008, and
  0010 amended; the [command-line reference](../../reference/cli.md), the
  [documentation index](../../README.md), and the core README (the PHP
  helper's native commands).

## Limitations and follow-ups

- An Xdebug branch is a basic block counted when entered, so an `if`
  without `else` whose condition is always true covers every block. Only a
  short-circuit operand, a ternary arm, or a `match` arm that is not taken
  leaves a branch missed while every line is covered (decision 0005).
- Two PHP 8.4 compilation details make Xdebug report less than the tests
  reach: an unqualified call to a frameless function inside a namespace adds
  a fallback block no test enters, and a method called only through a
  first-class callable records its hits under its bare name. The helper uses
  `use function` imports and closures; decision 0013 names both remedies.
- PHP and Xdebug are system programs pinned to minor versions; patch
  versions can differ between machines. PCOV is a prerequisite of the core's
  acceptance suite only, which needs it to prove the PCOV refusal.
- A source file that runs code when it is loaded is measured only when a
  test loads it; until then it fails as unmeasured.
- PHPStan extensions and included configuration are not loaded, because the
  component's `phpstan.neon` is not read; a rule that needs one takes a
  reviewed exception. While one file has a syntax error, PHPStan reports no
  other file.
- The helper resolves no dynamic class name (`new $class`) and no `include`
  path that is computed or relative without `__DIR__`; neither becomes a
  dependency edge, and a class outside the PSR-4 prefixes resolves to
  nothing.
