# P06 Complete TypeScript

Status: DONE

Implementation commit: `5ce8b5b` (feat(typescript): add the TypeScript profile,
Node helper, and acceptance suite).

## Delivered

- TypeScript profile ([decision 0011](../../decisions/0011-typescript-profile.md)):
  - configuration checks (`typescript.config`): `package.json`, a
    `package-lock.json` in the component or its workspace root that locks
    the pinned TypeScript, ESLint, typescript-eslint, Prettier, Vitest, and
    V8 coverage packages, `tsconfig.json`, a flat ESLint configuration, and
    no JavaScript among the source and test files;
  - Prettier (`typescript.format`), ESLint with type information
    (`typescript.lint`), and the compiler over the project reference graph
    in strict mode (`typescript.types`), run on the candidate snapshot with
    the pinned Node. Each lock directory is installed once per work area
    with `npm ci --offline --ignore-scripts` and empty npm configuration;
  - Vitest suites through a configuration the gate writes: it imports the
    component's own and overrides the test files, the JUnit reporter, and V8
    coverage of the source roots, remapped to the original sources;
  - safe fixes (`quality fix`): `prettier --write` and `eslint --fix` in a
    temporary copy, copied back only over unchanged working-tree files.
- The Node helper `tools/quality/helpers/typescript`, a TypeScript program
  Node runs directly. It type-checks, measures structure with the counting
  rules of decision 0007, resolves imports with each project's module
  resolution, and probes the ESLint configuration of every file. It is a
  `helper` component of this repository with 62 Vitest tests at 100% line
  and branch, and its sources are judged with the core (decision 0004).
- Engine: a profile's measurements feed the structure and architecture
  gates, and an exception for such a finding counts as unused only when its
  component was checked.
- Toolchain: Node 24.22.0 is a SHA-256-verified tool of
  `tools/quality/toolchains.toml`, unpacked whole; the npm packages every
  component must lock are pinned under `[packages.npm]`. Bootstrap installs
  Node and fills the npm cache only for a TypeScript component; doctor
  locates Node and installs offline (decision 0010).
- The configuration readers and static-check targets that both profiles use
  moved from `adapters/python` to `adapters` (decision 0003).
- Testkit: a fake Node and npm for unit tests (`testkit/nodefakes.py`) and
  scratch TypeScript components locked offline from the shared npm cache
  (`testkit/typescriptproject.py`).
- What the first acceptance run taught, fixed in the cases; the gate was
  right both times:
  - dropping `vitest` from `devDependencies` does not unlock it, because npm
    installs it as a peer of `@vitest/coverage-v8`, so the commit passed.
    The missing-driver case removes the coverage driver instead;
  - `.tsx` modules need the `jsx` compiler option; without it the compiler
    reports TS6142 and the gate rejects the commit.
- Documentation: decision 0011; decisions 0001, 0002, 0003, 0004, 0007,
  and 0010 amended; the [command-line reference](../../reference/cli.md)
  and the core README (the helper's native commands).

## Limitations and follow-ups

- Configuration files run code: `vitest.config.*` and `eslint.config.*` are
  imported by the check. The gate overrides what decides the verdict;
  anything else they do is reviewed with the change (decision 0011).
- Unit tests are not isolated from the network, as for Python; R06.9 stays
  open.
- V8 decides what is a line and a branch; the semantics are those of
  decision 0005.
- The type check costs about 1.5 seconds per project of the reference
  graph, and each TypeScript commit check takes 10–20 seconds on the
  reference machine.
- JSON configuration files are not formatted.
- `self-test` runs the suites of the `tooling` components; the helper's
  unit suite runs in `check` and `test`, like any other component's.
- Dart and PHP follow in P07 and P08.
