# P03 Implement common policy and documentation gates

Status: DONE

Implementation commit: `3c8f402` (feat(gates): add common file, docs,
secret, structure, and exception gates).

## Delivered

- `quality check [--staged|--rev REV] [--json]` checks every file of the
  isolated candidate, in this order:
  - blob size, source file length, and UTF-8 encoding;
  - JSON (duplicate keys included), TOML, and YAML syntax;
  - inline suppression markers;
  - documentation rules;
  - PyMarkdown structure lint, with a configuration owned by the core;
  - gitleaks secret scan;
  - for Python components, structure metrics and declared module
    architecture.

  Profiles that are not implemented yet report `profiles.unavailable`, an
  environment error, instead of passing.
- Python structure metrics use `ast` and `tokenize`: code lines, cyclomatic
  complexity, nesting, and parameters per function at any depth. Files that
  cannot be parsed, including pathologically nested ones, fail. The exact
  counting rules are in
  [decision 0007](../../decisions/0007-common-gates.md).
- Module architecture: module globs, an ordered `layers` list, and
  `forbidden` edges. Absolute and relative imports are resolved, and
  overlaps and cycles fail. The core declares its own layers in
  `quality.toml` and is checked against them.
- Documentation rules:
  - page and agent-file limits; a missing `AGENTS.md` fails;
  - case-sensitive internal links and anchors, with line anchors on
    non-Markdown targets;
  - every page must be reachable from the index;
  - documented `quality` commands are checked against the CLI command
    table;
  - non-English prose gives an advisory warning only.
- Inline suppressions: each marker is a finding until it is registered as
  an exception. This covers:
  - Python comments, found with the tokenizer (with a line scan as
    fallback);
  - TypeScript, JavaScript, Dart, and PHP comment markers;
  - PyMarkdown markers in documentation;
  - the gitleaks allow marker in any file;
  - `.gitleaksignore` entries.
- Secrets: the pinned upstream rule set, with only the global path
  allowlist removed (verified). gitleaks runs with `--ignore-gitleaks-allow`
  and `--redact`, scans binaries and archives (depth 3), and the candidate's
  own gitleaks configuration and ignore files cannot change the result.
  `check_history` scans every blob that a revision range adds, including
  blobs deleted again before the tip, for size and secrets.
- Exceptions match exact rule, path, and symbol. The checks:
  - an expired exception fails and stops applying;
  - a past review date warns;
  - an exception that matches nothing fails, but only for rules that ran
    over the whole candidate;
  - policy, Git, discovery, secret, and exception rules cannot be excepted.
- `quality links [--rev REV] [--timeout S] [--json]` probes external links
  in the documentation, separately from `quality check`:
  - only hosts whose every address is public are probed, at the validated
    addresses;
  - redirects are revalidated at every hop;
  - no response body is read;
  - 404 and 410 are errors; other failures are warnings.
- `quality tools install [NAME...]` installs pinned standalone tools from
  `tools/quality/toolchains.toml`. Each download is checked against its
  SHA-256 and goes through a staging directory. Archive member paths are
  validated, and stale installations are replaced.
- Repository adoption:
  - root `quality.toml` with the template defaults and two registered
    exceptions for existing `noqa` markers;
  - `AGENTS.md`;
  - the documentation index `docs/README.md`;
  - [decision 0007](../../decisions/0007-common-gates.md);
  - decisions 0001, 0002, and 0004 and the core README updated.

## Limitations and follow-ups

- Profile gates exist only for Python (structure and architecture). The
  formatter, lint, type, and test gates arrive in P05. TypeScript, Dart, and
  PHP report `profiles.unavailable` until P06–P08.
- `check_history` is a library function; merge CI calls it in P10, along
  with the dependency audit and the scheduled external link check. A12 stays
  open until then.
- The gate is run through `python -m quality` until the launcher and hooks
  exist (P05). Changed-line rules and coverage arrive in P04.
- External link results depend on the network; failures other than 404 and
  410 are warnings by design.
- The pymarkdown and gitleaks behaviour that the gate relies on (absolute
  output paths, the root `.gitleaksignore`) is pinned by tests against the
  pinned versions. A tool update must rerun those tests.
