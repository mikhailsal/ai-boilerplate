## Delivered

- The merge gate ([decision 0015](../../decisions/0015-ci-wrappers-and-merge-gates.md)):
  - `quality gate --stage commit|merge` checks every active component of
    one candidate named by explicit revisions: the index, a pushed range
    (`--base`, `--head`, a zero base for a new branch), a pull request
    (`--base`, `--head`, `--tested`), or a merge-queue entry (`--queue`).
    A pull request owns only its lines against the merge base, while the
    tested merge is what runs; arguments that describe no single candidate
    fail with `gate.arguments`;
  - a range scans every blob of its new commits for secrets and the blob
    size limit, so a secret or a large file removed before the tip still
    fails; shallow or incomplete history fails with
    `git.revision-unresolvable` instead of shrinking the check;
  - `--reports DIR` writes into a new or empty directory: `report.json`,
    JUnit per suite, LCOV and Cobertura per unit suite, and copies of the
    native reports, all with repository-relative paths and only from valid
    results (`reports.incomplete` when writing fails);
  - `--baseline FILE` compares unit coverage with an earlier report:
    `coverage.regression` and `coverage.baseline` are warnings, never a
    ratchet.
- The required status: `quality ci verdict --needs FILE [--rev REV]` reads
  `toJSON(needs)` and fails unless every job in `[ci].required_jobs`
  succeeded (`ci.job-failed` for failed, cancelled, and skipped jobs,
  `ci.job-missing`, `ci.job-unexpected`, `ci.results` for unusable input or
  a revision without `[ci]`).
- Workflow rules on every check (`quality.ci`): `ci.aggregate` (the
  required workflow runs on `pull_request` and `merge_group`, its aggregate
  job runs `if: always()`, needs exactly the required jobs, and calls the
  verdict with `toJSON(needs)`; required jobs have no `if`),
  `ci.path-filter`, `ci.unpinned-action` (actions, reusable workflows, and
  images pinned by commit SHA or digest), `ci.privileged-trigger`
  (`pull_request_target`, `workflow_run`), `ci.permissions`,
  `ci.persisted-credentials`, `ci.continue-on-error`, `ci.secret`, and
  `ci.actionlint` from the pinned actionlint 1.7.12 with a configuration
  owned by the core. actionlint and osv-scanner are now default tools of
  `quality bootstrap`.
- Control files: derived from the policy (the policy, the launcher,
  `.gitattributes`, `.github`, `.gitlab-ci.yml`, tooling and helper roots,
  scenario manifests, native configuration) plus `[ci].control`.
  `ci.codeowners` requires an owner for each, including CODEOWNERS itself,
  reads CODEOWNERS as GitHub does (last match wins, unsupported syntax and
  owners reported), and reports a CODEOWNERS file that GitHub reads first.
  At the merge stage `ci.control-changed` lists every changed control file.
- Dependency gates: `uv lock --check --offline` before a Python environment
  is synced (`python.config` at `uv.lock` when it is stale), next to the existing
  `npm ci`, `dart pub get --enforce-lockfile`, and `composer validate
  --check-lock`. `quality audit [--rev REV] [--offline-db DIR]` scans every
  lockfile classified as configuration with the pinned osv-scanner 2.7.0;
  the `[audit]` table sets the blocking CVSS score (7.0) and the grade of
  unscored advisories (error); a scanner, network, or database failure is
  `dependencies.scanner` (exit 3), never a clean result.
- Wrappers: [`.github/workflows/quality.yml`](../../../.github/workflows/quality.yml)
  with `gate`, `audit`, and the aggregate `required`, pinned actions, no
  default permissions, caches restored from and saved only by the default
  branch, and the PHP runtime with Xdebug and PCOV; the GitLab reference
  wrapper [`ci/gitlab/quality.gitlab-ci.yml`](../../../ci/gitlab/quality.gitlab-ci.yml)
  with the same entry points and an image pinned by digest.
- Protection preparation: [`.github/CODEOWNERS`](../../../.github/CODEOWNERS),
  the branch ruleset [`.github/rulesets/main.json`](../../../.github/rulesets/main.json)
  (pull requests only, code-owner review, the `required` status from the
  GitHub Actions app, up-to-date branches, no bypass actors), and the
  [protection guide](../../guides/protection.md) with the real boundary.
- Fixes from the first hosted run (see [Hosted status](#hosted-status)):
  - `strictjson`, a new lowest layer, parses JSON with an explicit bound of
    512 nested containers and rejects NaN and Infinity. The standard decoder
    stops deep input when the C stack runs low, so a document could parse on
    one machine and fail on another. Reports, native configuration, the
    `config.syntax` rule, and manifest discovery use it;
  - TOML and YAML that nest beyond the parser's recursion limit are reported
    by `config.syntax`, manifest discovery, the policy loader, and the
    scenario manifest loader instead of escaping as an internal error;
  - scratch TypeScript components lock offline from the helper's lockfile,
    because `npm ci` caches package tarballs but not the registry metadata
    that resolving versions needs;
  - the stale-lock unit test no longer depends on a warm uv cache;
  - the `gate` job lifts the AppArmor restriction of Ubuntu 24.04 on
    unprivileged user namespaces, and the `audit` and `required` jobs no
    longer bootstrap every component (which needs PHP 8.4): the audit installs
    only the scanner, and the launcher installs the core.
- This repository: `[ci]` and `[audit]` in `quality.toml`, the `ci`,
  `reports`, and `strictjson` layers, and the `merge-gate` scenario of the
  core.
- Documentation: decision 0015, the protection guide, decisions 0002,
  0003, and 0004 amended, the [command-line reference](../../reference/cli.md),
  the [documentation index](../../README.md), the core README, and
  `AGENTS.md`.

## Limitations and follow-ups

- Server enforcement is unverified until an owner applies the ruleset and
  observes a rejected direct push and a blocked failing pull request, as
  the [protection guide](../../guides/protection.md#confirming-the-protection)
  describes.
- A sole maintainer cannot satisfy the code-owner review of their own pull
  request; the guide leaves the choice between a second maintainer and an
  audited admin bypass to the owner.
- Merge queues are unavailable for repositories owned by a user; the
  workflow handles `merge_group`, and the up-to-date requirement replaces
  the queue until then.
- The gate runs the candidate's own core, so a pull request can change the
  validator it is judged by; code-owner review of the control files is the
  protection, and a trusted external validator is a future option.
- GitLab has no equivalent of `needs` results in one job, so the pipeline
  status is the required status there; no offline GitLab linter was run.
- `quality audit` needs the osv.dev API or a downloaded database; advisory
  freshness is therefore not part of `check`, and an exception covers one
  advisory in one lockfile until it expires.
- The coverage baseline and the download cache are saved only by a push to
  the default branch; until the first such push, pull requests run without
  the comparison and download every tool. Regressions are warnings; the
  floors decide.
- The hosted runs proved the workflow on `pull_request` events only;
  `merge_group` and `push` to main have not run on the host yet.
