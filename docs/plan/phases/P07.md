## Delivered

- Dart profile ([decision 0012](../../decisions/0012-dart-profile.md)):
  - configuration checks (`dart.config`): `pubspec.yaml` with a package
    name, a `pubspec.lock` in the component or the root of its pub
    workspace that locks the pinned package:test, package:coverage, and
    package:lints from a hosted source, path packages inside the
    repository, every `analysis_options.yaml` of the component at the
    strict floor, and a `dart_test.yaml` that tunes only timeouts,
    concurrency, and stack traces. Flutter packages and web compilers are
    rejected as unsupported variants before any tool runs;
  - `dart format` (`dart.format`) and `dart analyze --fatal-infos` over
    the Dart files, the component's `pubspec.yaml`, and every analysis
    options file, split into lints (`dart.lint`), problems in those
    configuration files such as a deprecated lint (`dart.config`), and every
    other diagnostic (`dart.types`). Both run on the candidate snapshot with
    the pinned SDK, a private home, and the shared pub cache. Each lock
    directory is resolved once per work area with
    `dart pub get --offline --enforce-lockfile`;
  - unit suites through `dart test --platform vm --branch-coverage` over
    the declared roots plus a generated test that imports every library of
    the source roots, the JSON file reporter for results, and the
    component's own package:coverage for LCOV of each source root. Files
    the generated test compiles without a coverable line count as measured;
  - safe fixes (`quality fix`): `dart format` and `dart fix --apply` in a
    temporary copy, copied back only over unchanged working-tree files.
- The Dart helper `tools/quality/helpers/dart`, a Dart program on the pinned
  package:analyzer, compiled once to a kernel snapshot in the toolchain
  cache. It measures functions, complexity, nesting, lines, and names with
  the counting rules of decision 0007, including closures, nested and
  expression-bodied functions, and resolves imports, exports, conditional
  imports, and parts. It is a `helper` component of this repository with
  73 tests at 100% line and branch.
- Network isolation for every profile (R06.9,
  [decision 0008](../../decisions/0008-test-and-coverage-engine.md#network-isolation)):
  unit suites start behind a stub on the core interpreter that enters a new
  user and network namespace, brings loopback up, and executes the runner.
  Loopback works, so the Dart VM service and coverage do; every other
  address is unreachable. Where unprivileged user namespaces are disabled,
  the suite runs as before and the check warns with `tests.network`.
- Engine: results are parsed per format (JUnit XML or the Dart JSON
  reporter); a JSON report without its `done` event, a malformed or
  repeated event, or an unknown test is a report error. `tests.failed` now
  names the first five failing tests in every profile. The process runner
  can reap a command's process group after a normal exit, so no VM service
  outlives a run.
- Toolchain: Dart SDK 3.13.6 is a SHA-256-verified zip of
  `tools/quality/toolchains.toml`, unpacked whole; the pub packages every
  component must lock are pinned under `[packages.pub]`. Bootstrap installs
  the SDK, fills the pub cache, and compiles the helper only for a Dart
  component; doctor resolves offline (decision 0010).
- Shared adapter code: the copy-back of safe fixes and the helper request
  and answer files moved to `adapters/copies.py` and `adapters/helperio.py`,
  used by the TypeScript and Dart profiles.
- Testkit: a fake Dart SDK (`testkit/dartfakes.py`) and scratch Dart
  packages and workspaces locked offline from the shared pub cache
  (`testkit/dartproject.py`).
- Documentation: decision 0012; decisions 0001, 0002, 0004, 0005, 0006,
  0007, 0008, 0009, 0010, and 0011 amended; the
  [command-line reference](../../reference/cli.md) and the core README (the
  helper's native commands).

## Limitations and follow-ups

- Dart instruments function entries, call sites, and block entries only:
  a literal `return` has no line, and `&&`, `??`, and conditional
  expressions are no branch opportunities (decision 0005). The floors apply
  to what the VM measures.
- The helper does not count `when` guards in complexity; a nested
  function's lines also count toward the enclosing function's length; every
  file is parsed at the latest language version; an import with an
  interpolated URI has no edge; a closure that is a map value is named
  `<anonymous>`.
- Network isolation needs unprivileged user namespaces. Where they are
  disabled, for example by Ubuntu's AppArmor restriction, unit suites run
  with the network and the check warns (`tests.network`); that path is
  covered by unit tests, not observed on a restricted machine. Integration
  and other suites are not isolated. R06.9 stays open until PHP.
- `build_runner` is never run: generated Dart files are committed and
  classified `generated` explicitly.
- The helper is compiled on first use after a change to it or to the SDK,
  about 16 seconds; a warm Dart commit check takes about 20 seconds on the
  reference machine.
- `dart fix --apply` applies the analyzer's own fixes; as with every fix,
  the change is reviewed and staged by hand.
- PHP follows in P08.
