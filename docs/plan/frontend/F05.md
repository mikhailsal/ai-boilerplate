# F05 Implement production browser scenarios and accessibility

Status: DONE

## Scope

The merge-stage path of a browser component
([decision 0018](../../decisions/0018-browser-builds-and-scenarios.md)):
the candidate's production build, served by the gate's own server, its
end-to-end suites in the pinned Chromium through the scenario registry, and
the console, resource, accessibility, and keyboard evidence they leave. The
reference application, deferred from F03, is the `example` component
`example-web`, checked in maintainer mode.

## Changes

| Area | Change |
| --- | --- |
| `adapters/typescript` | `serve`: the build on `127.0.0.1` at an assigned port, client-route fallback, missing files recorded; `playwright`: the generated configuration and gate reporter in a reaped session; `endtoend`: build, serve, run, and judge; `traces`: console, page, and resource errors; `scans`: axe evidence and violations; `browser`: `typescript.browser-incomplete` removed; `environment`: Node's compile cache off |
| `testing`, `engine` | The Playwright report as suite results, with the evidence of each case |
| `scenarios`, `policy` | A scenario's `boundary`, `scenarios.evidence`, browser-only `ui.accessibility` and `ui.keyboard`, `accessibility_tags` |
| `cli` | The check and the reports repeat the tested boundaries; the pinned Chromium for the profile |
| `testkit` | `browserscenarios`: the generated counter's scenarios and manifest |
| Acceptance | `test_browser_scenarios.py`: the counter proved despite a stale `dist/`, an unrelated server, and a configuration with retries, a filter, another browser, and a reused server; twelve broken cases. `test_browser_runs.py`: a missing browser, cleanup, and the merge gate's native evidence |
| `examples/web` | Two pages and a not-found page with client routing, a feedback form with focus on its problems, CSS Modules, an imported image, a public icon, and loading, success, and error states; jsdom units at 100%; four scenarios in both viewports |
| Documentation | Decisions 0014, 0017, and 0018, the profile matrix, the core README, the example README |

The twelve broken cases are: a page that cannot start, a crashed page, a
broken asset, a missing response, a scan of an empty page, low contrast, a
console error with and without an exception, a skipped scenario in every
viewport and in one, a focused scenario, and a configuration that cannot
load. Each finds exactly the rules it breaks; the excepted error finds none.

## Limitations

- A renderer crash after a test's last step is not detected.
- The `browser` CI job, the wrappers, and the stage matrix are F06;
  decision 0018 stays proposed until then.
- `component add --target browser` registers an application with only its
  unit suite; the example's end-to-end suite and manifest were added by
  hand (F07).
- A change of `quality.toml` affects every component, so a merge-stage check
  of this repository runs the core's whole acceptance suite. The example's
  scenarios were proven with `quality test`; the full merge gate is F08.
- Incomplete axe results are reported as information only.
- `/tmp/node-compile-cache`, about 8.1 GB from runs before the fix, is left
  for the user to remove.
