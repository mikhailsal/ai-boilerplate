# F04 Implement component unit coverage in the strict commit gate

Status: DONE

## Scope

The unit suites of a browser component in the commit gate, with the base
coverage floors
([decision 0017](../../decisions/0017-browser-frontend-profile.md#unit-tests-and-coverage)),
and the candidate semantics of decision 0004 proven with frontend files. The
reference application stays in F05 (see the [F03 record](F03.md#scope)), so
the tests run on generated browser projects: the testkit component gains a
test of its entry point, and the acceptance cases add hooks, conditional
JSX, and a library component.

## Changes

| Area | Change |
| --- | --- |
| `adapters/typescript` | `runner`: every suite of a browser component except end-to-end runs in jsdom with `expect.requireAssertions`, merged over the component's own `expect` options; `profile`: only an end-to-end suite of a browser component still raises `typescript.browser-incomplete`; `browser`: the missing gates are the production build in the gate, the Chromium scenarios, and the accessibility scans |
| `testkit` | `browserproject`: `tests/main.test.tsx` covers the entry point, with and without its root element |
| Acceptance | `test_browser_units.py`: the floors one at a time, an unimported TSX file, conditional JSX, a test without assertions, shared source, and end-to-end separation; `test_browser_candidate.py`: staged versus work tree for a TSX source, a test, the Vite configuration, a stylesheet, and an asset, a first commit, and a commit of named paths; `test_browser_static.py`: a secret in a stylesheet and an oversized asset, and the cases whose fixtures the unit suite now runs |
| Documentation | Decisions 0011 and 0017, the profile matrix |

A check of a browser component now prints `typescript.browser-incomplete`
once, for its static gates; its unit suite passes or fails on its own.

## Limitations

- A browser component still fails every check, bootstrap, and doctor with
  `typescript.browser-incomplete`, and cannot name a scenario manifest,
  until F05; a check of it exits 2.
- The first jsdom test of a file took up to 2.8 s of Vitest's 5 s default
  timeout with seven runs at once. In the acceptance run with 6 workers the
  entry test failed once and passed in every other check; the browser
  modules ran with 4 workers.
- The reference application's suites (FR04.1) and the Playwright runner
  (FR04.6) are proven in F05.
