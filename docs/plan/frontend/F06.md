# F06 Integrate the existing CLI and portable CI

Status: DONE

## Scope

The stages of a browser component in the existing gate and wrappers
([decision 0018](../../decisions/0018-browser-builds-and-scenarios.md#stages-and-ci),
[decision 0015](../../decisions/0015-ci-wrappers-and-merge-gates.md)): the
gate split into two lanes that CI runs as required jobs, a `browser` job in
the GitHub workflow and the GitLab reference wrapper, the aggregate status
over both, and the browser settings as control files.

| Area | Change |

| `ci` | `lanes`: `Lane`, the partition of components, and `ci.lanes`, which fails required jobs that run one lane without the other; the aggregate check runs it |

| `ci/gitlab/quality.gitlab-ci.yml` | One hidden job with `QUALITY_LANE` for `gate` and `browser`; the Chromium libraries verified in the pinned image; JUnit from `reports/junit/*/*.xml`, where the gate writes it |
| Tests | `ci/test_lanes.py`, `engine/test_lanes.py`, the verdict, aggregate, control, and CLI tests; `test_ci_wrappers.py` runs the real policy and workflow through failed, cancelled, skipped, and missing browser jobs; the acceptance case `browser-lanes` |

## Limitations

- Neither the GitHub `browser` job nor the GitLab wrapper has run on its
  host; the ruleset is still not applied.
- The GitHub job relies on the runner image's Chromium libraries; without
  them bootstrap fails with `typescript.browser-libraries` (exit 3) instead
  of passing.
- Browser jobs activate per active browser component, not per affected
  change: the gate checks every active component
  (decision 0015), so the example's scenarios run in every pull request
  here. Without a browser component the lane passes with nothing to check,
  after bootstrap.
- The main lane of this repository needs Chromium too, because the core's
  acceptance suites drive browsers.
- The full merge gate of this repository, with the core's acceptance suite,
  is F08.
- An unprivileged container cannot isolate the network of unit suites, so
  each suite warns with `tests.network`; an unprivileged GitLab Docker
  runner, not tried, would presumably do the same.
- The audit finding has no fixed release; `7dfbb3b`, during F07, adds
  dated exceptions for it.
