# F07 Prove reuse and publish bounded local documentation

Status: DONE

## Scope

A browser application in projects made from the template: the README's
Quick start, run as written from a fresh export, from a TypeScript Node
project, and twice in one project, and the documentation that a project
needs for it ([decision 0017](../../decisions/0017-browser-frontend-profile.md#registration),
[decision 0016](../../decisions/0016-template-lifecycle.md)).

## Changes

| Area | Change |
| --- | --- |
| `cli`, `policy` | `component add` registers a browser application's `e2e` directory and `scenarios.toml` when they exist; `--e2e` and `--scenarios` name them for any component |
| Acceptance | `test_frontend_start.py` runs the Quick start block of the exported README line by line in a shell; `conftest.py` shares the template clone, the export, and the limited caches with `test_template.py`; `a16` expects the shipped example to stay dormant |
| `README.md` | "A browser application": copy the reference application, rename its manifest's component, register, stage, bootstrap, commit, and run both suites; adding a frontend to an existing project and a second application |
| Documentation | The profile matrix's "Browser applications" with supported and unsupported variants and budgets; browser findings in the exceptions guide; the reference application in the maintenance guide; the CLI reference; decision 0017 |
| `tools/quality/scenarios.toml` | The scenario `frontend-start` |
| `quality.toml` | Exceptions for GHSA-vfj7-8cjw-p6xm in the two template lockfiles that lock `braces` 3.0.3, expiring on 2027-01-22; the README tells a project to do the same for its copy |

The first CLI invocation is `./quality` at the repository root, the
launcher, which prepares the core on first use; nothing has to be on `PATH`.

The three Quick start cases prove:

- A fresh export bootstraps without Chromium. The Quick start's commit runs
  the static checks and unit suites (`web` line coverage 100%; its 4
  scenarios not required by the commit stage), `quality test` proves the 4
  scenarios in Chromium, a repeated bootstrap reports the browser ready, and
  the work tree stays clean with the export's root commit and one more.
- A TypeScript Node project bootstraps and commits its `api` component with a
  cache holding only uv, gitleaks, actionlint, osv-scanner, and Node; doctor
  names no Chromium and the cache holds none. The same project then adds the
  frontend through the Quick start, and the hook checks `api` and `web`.
- Two applications from the Quick start, `web` and `admin`, pass the hook,
  and the browser lane at the merge stage proves both 4 of 4.

## Limitations

- The Quick start starts from the reference application rather than a native
  scaffolder; a project made with `npm create vite` still needs the end-to-end
  suite, the scenario manifest, and the capability declarations that the
  reference application shows.
- The cases run on this host only; the generic Linux container is recorded in
  [F06](F06.md).
- A project's copy of the reference application locks `braces` 3.0.3 as
  well, so its `audit` job fails until the project adds its own dated
  exception or a fix is released. The acceptance cases do not run the
  audit, which needs the advisory database from the network.
