# F02 Prepare the frontend environment and startup operations

Status: DONE

## Scope

The browser package pins, the pinned Chromium, and their preparation and
report in `quality bootstrap` and `quality doctor`
([decision 0017](../../decisions/0017-browser-frontend-profile.md#chromium)).
The frontend Quick start moved to F07, where it can pass.

## Changes

| Area | Change |
| --- | --- |
| `toolchains.toml` | `[tools.chromium]`: the Chrome for Testing headless shell 156.0.8078.4 for x86_64 and aarch64 with SHA-256 pins; `[packages.npm-browser]`: the React, Vite, testing, lint, CSS, and Playwright pins |
| `adapters/typescript` | A browser component's lockfile must lock the browser pins; `chromium`: `ldd` and `--version` probes, the Playwright chain to `browsers.json`, and the rules `typescript.browser-libraries`, `typescript.browser-version`, and `typescript.browser-ready`; provisioning installs or locates Chromium only for an active browser component |
| `engine` | A component with only information or warning findings is reported ready |
| `cli` | `local_setups` passes the pinned Chromium; the npm pins merge both tables |
| `testkit` | `browserfakes`: browser pins, a fake playwright-core, a fake headless shell and `ldd` |
| `ci` | The control-change explanation names example roots |
| Documentation | Decisions 0002, 0015, and 0017, the maintenance guide, the command reference, the profile matrix |

Node-only projects are unchanged: acceptance projects lock only
`[packages.npm]`, and neither bootstrap nor doctor reads the browser for a
component whose target is `node`.

## Limitations

- A browser component still fails every check, bootstrap, and doctor with
  `typescript.browser-incomplete` until F05.
- Chromium has no vendor SHA-256: its pins were computed from downloads that
  matched the bucket's MD5, and `tools update` refuses it.
- The aarch64 archive was hashed but not run: this machine is x86_64.
