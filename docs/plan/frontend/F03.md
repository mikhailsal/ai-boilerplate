# F03 Implement static checks and production building

Status: IN_PROGRESS

## Scope

The static checks of a browser component
([decision 0017](../../decisions/0017-browser-frontend-profile.md#static-checks))
are done; the isolated production build
([decision 0018](../../decisions/0018-browser-builds-and-scenarios.md)) is
the remaining F03 task.

The reference application moves to F05. An `example` component is checked
in maintainer mode, so registering it while every browser component fails
with `typescript.browser-incomplete` would fail every maintainer commit, and
the assignment forbids a permissive switch. Until F05 the gates are proven
on generated browser projects instead: the testkit writes a React + Vite
component and locks it from a committed seed lockfile.

## Changes (static checks)

| Area | Change |
| --- | --- |
| `helpers/typescript` | `imports` command: each import resolved with the component's tsconfig, with builtin and type-only marks; `eslint-config` returns the severity of each requested rule per file |
| `adapters/typescript` | `browser`: the required React Hooks, 18 `jsx-a11y-x`, and test rules, unsupported style variants, server modules; `boundaries` (`typescript.boundaries`); `stylelint` (`typescript.styles`) with a gate-written configuration over the baseline; `entries` (`typescript.entries`) with Vite's resolution; Prettier formats and checks CSS and HTML entry points; `fix` formats them too |
| `discovery` | `dist/` is generated and `public/` holds assets in a browser component; source maps are generated; CSS, HTML, SVG, and images are assets |
| `rules` | `stylelint-disable` and `prettier-ignore` in CSS, and `prettier-ignore` in HTML, are inline suppressions |
| `testkit` | `browserproject`: a React + Vite component locked offline from `browserseed/package-lock.json`; scratch projects and fakes use it |
| Documentation | Decisions 0011 and 0017, the profile matrix, the core README |

The checks run in every check of a browser component, which still fails
with `typescript.browser-incomplete` beside their findings.

## Limitations

- A browser component still fails every check, bootstrap, and doctor with
  `typescript.browser-incomplete` until F05; a check prints it twice, once
  for the static checks and once for the unit suite.
- A browser component cannot name a scenario manifest before F05, so its
  check also reports `scenarios.manifest` and exits 2.
- `quality fix` formats CSS and entry points but runs no Stylelint fixes;
  it reads no policy, so it also formats the CSS of a nested component.
- The seed lockfile is test data; `quality audit` scans it like any other
  lockfile.
